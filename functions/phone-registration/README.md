# رقم واحد لحساب واحد — الإصدار المنسق

العميل والمشترك يتشاركان نفس مساحة أرقام الدخول. الأرقام المحلية والدولية والأرقام العربية والفارسية تُحوّل إلى الصيغة المصرية الموحدة. لا توجد SMS، ولا يُعتبر هذا إثباتًا لملكية الشريحة.

الموقع والعميل الجديد يتحققان من الرقم قبل إنشاء Auth ثم يكملان الملف والفهرس الخاص في معاملة خادم. نفس الحساب ونفس النوع قابلان لاستكمال التسجيل؛ الحساب الموجود لا يُنقل إلى نوع آخر عبر التسجيل.

العملاء المنشورون v5 يرسلون بالفعل phone وphoneNormalized وبريد Auth التقني الموحد. يُقبل إنشاؤهم المباشر فقط مع مطابقة هذه الحقول، وتفرّد بريد Auth الذي يفرضه Firebase، وعدم وجود حجز لرقمهم لحساب آخر. يُجهّز memberPhoneIndex/{canonicalPhone} للأعضاء الحاليين قبل تفعيل القاعدة. السجل خاص بالخادم؛ لا يمكن للمستخدمين قراءته أو كتابته. الحقول الشخصية الموجودة لا تُعدّل أثناء التجهيز.

إذا وُجدت بيانات قديمة مكررة يُحجب التسجيل الجديد للرقم دون حذف أو دمج الحسابات. فحص البيانات القديمة يقرأ إسقاط حقول الأرقام عندما لا يوجد فهرس؛ يجب مراقبة التكلفة مع نمو المنصة. تغيير رقم دخول موجود يُراجع إداريًا لأن تعديله من الملف محمي بالقواعد.

## النشر

مسار readiness يبني الواجهات ويختبر الوظائف، ويقرأ القواعد الحية وفهرس الأرقام دون تعديل الإنتاج. تُختبر إضافة الحماية على القواعد الحية في المحاكي. مسار الإنتاج المخصص ينشر الوظائف المسماة فقط، ويجهّز الفهرس، وينشر إضافة Firestore المحدودة والموقع. لا يُشغّل تنظيف المنشورات ولا يغيّر Storage Rules.

لم يشمل هذا التعديل حذف حسابات قديمة. عند إكمال مسار حذف الحساب مستقبلًا يجب تحرير حجز الرقم بعد حذف Auth والعضو بنجاح. قد تحتاج هويات Auth القديمة التي لا تملك ملفًا مكتملًا إلى إصلاح إدارة إذا لم تبقَ جلسة دخول صالحة؛ لا تُحذف ولا تُنقل تلقائيًا.
