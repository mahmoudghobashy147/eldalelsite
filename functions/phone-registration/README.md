# رقم واحد لحساب واحد — تعديل غير منشور

- `assertMemberPhoneAvailable` يتحقق من السجل الخاص ومن الأعضاء الحاليين قبل إنشاء Firebase Auth لتفادي إنشاء هوية دخول ثانية للبيانات القديمة.
- `completeMemberRegistration` يطابق الرقم مع البريد التقني في رمز Firebase Auth ثم ينشئ مستند العضو وحجز الرقم في معاملة واحدة. النوع لا يدخل في مفتاح الحجز؛ العميل والمشترك يتشاركان نفس مساحة الأرقام.
- سجل `phoneRegistrations/{SHA256(canonicalPhone)}` خاص بالخادم، وكذلك `registrationAttempts`. لا توجد صلاحيات قراءة أو كتابة للعميل في القواعد.
- Firestore Rules تمنع الإنشاء المباشر لمستندات الأعضاء وتحمي phone وphoneNormalized من تعديل العضو نفسه. الحسابات الحالية لا تُنقل ولا تُحذف؛ تغيير رقم الدخول يستلزم مسار إدارة مراجعًا.
- يدعم 01 و+20 و0020 والأرقام العربية والفارسية. هذه مطابقة وتفرّد للحساب، وليست إثبات ملكية رقم الهاتف، ولا تتضمن SMS.
- البيانات القديمة تُفحص عند التسجيل دون ترحيل جماعي. إذا لم يوجد حجز للرقم، يُقرأ إسقاط حقول أرقام الأعضاء الحاليين للتأكد من الصيغ القديمة؛ هذا له تكلفة قراءات ويجب مراقبته مع نمو المنصة. لا تُحل الحسابات المكررة الموجودة مسبقًا تلقائيًا ولا تُحذف.

## ترتيب الإصدار المطلوب

لا تنشر هذا التعديل منفردًا على القواعد. يلزم بناء الموقع ونسخة أندرويد الجديدة مع الوظائف والقواعد المتوافقة، وتجربة التسجيل بحساب اختبار ثم مراجعة النتيجة قبل النشر. نسخة أندرويد القديمة التي تنشئ مستند العضو مباشرة لن تتمكن من إنشاء حساب جديد بعد تشديد القواعد؛ يجب إتاحة النسخة المحدثة وإرشاد مستخدمي النسخ القديمة للتحديث. تسجيل الدخول للحسابات الحالية لا يتغير.

1. بناء نظيف بـ npm run build لتطبيق ملفات الربط والتأكد من الاختبارات.
2. مراجعة ونشر وظيفتي assertMemberPhoneAvailable وcompleteMemberRegistration فقط مع صلاحيات الاستدعاء العامة والتحقق البرمجي من Auth في الوظيفة الثانية.
3. تنسيق إصدار الواجهات الجديدة والقواعد المراجعة، واختبار التسجيل/الدخول/تعديل الملف على جهاز فعلي. لا يوجد نشر آلي ضمن هذا التعديل.
4. اختبارات فشل الشبكة بعد إنشاء Auth مهمة: قد توجد هوية Auth بلا ملف مكتمل كما في المسار القديم. لا تحذف هوية موجودة أو تنقل رقمًا إلى UID آخر تلقائيًا؛ تُراجع حالات الإصلاح من الإدارة.

عند إكمال حذف الحساب مستقبلًا، يُراجع حذف الحجز المرتبط بعد حذف Auth والعضو بنجاح، حتى لا يصبح الرقم محجوزًا لمستند مفقود. لا تُضاف أي عملية حذف إنتاجي هنا.
